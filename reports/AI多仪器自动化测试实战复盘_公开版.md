# 一个人、一台电脑和 AI：多仪器自动化测试实战复盘

**性质：真实操作总结**  
**完成时间：2026-09-04**  
**公开说明：被测芯片型号、设备地址、序列号和本机路径均已删除。**

## 结论先行

本次实践用一台 Windows 电脑和 AI 辅助，真实联动了四类实验室仪器，完成了两套不同的自动化测试闭环：

1. 程控电源与 SMU 联动，完成芯片导通电阻平坦度表征；
2. 信号发生器与示波器联动，完成波形循环切换、参数监控、逐点波形采集、CSV 日志和实时绘图。

AI 的作用不是代替仪器，也不是绕过安全控制直接“操作硬件”。操作者通过自然语言描述目标，AI 辅助阅读手册、诊断通信、生成和修改 Python 程序、分析数据、整理结果；真正执行仪器动作的是带白名单、限值、回读、超时和失败关断机制的确定性 Python/VISA/SCPI 程序。

本次结果证明：一个操作者可以用低软件成本完成从环境搭建、测试设计、通信排查、安全检查、程序实现到数据和报告的完整闭环。

## 实际使用的设备与软件

| 类别 | 实际使用内容 | 作用 |
|---|---|---|
| 程控电源 | RIGOL DP831，CH1 + CH2 | 提供芯片电源与输入偏置扫描 |
| SMU | Keithley 2400 | 输出 1 mA 测试电流并进行四线压降测量 |
| 信号发生器 | RIGOL DG1022Z，CH1 | 输出正弦波、方波和三角波 |
| 示波器 | RIGOL MSO5354，CH1 | 测量 Vpp、最大值、最小值和频率，并传输波形点 |
| 连接 | 四线 Force/Sense、10X 示波器探头、USB、串口和网线 | 完成低阻测量与信号观测 |
| 控制软件 | Windows、Python、PyVISA、NI-VISA、PyVISA-py | 统一访问不同通信接口的仪器 |
| AI 入口 | Codex App | 接收自然语言任务、辅助修改程序并展示控制过程 |

这不是四台同型号仪器的简单并联，而是两组不同测试任务、三种通信形态和多个 VISA 后端的组合：DP831 使用 NI-VISA USBTMC，Keithley 2400 使用 PyVISA-py 串口，信号源和示波器通过 PyVISA 抽象进行联动。

## 实测任务一：芯片导通电阻平坦度

测试采用以下流程：

```text
只读识别与状态检查
        ↓
确认所有相关 OUTPUT 为 OFF
        ↓
配置 DP831 供电与输入偏置
        ↓
Keithley 2400 输出 1 mA，四线测量压降与电流
        ↓
计算 RON = |Vdrop| / |I|
        ↓
逐点保存原始数据和状态字
        ↓
异常中止 / 最终关断 / 生成曲线
```

关键安全设计包括：

- 先单点验证，再扩大到完整扫描；
- SCPI 写操作使用封闭白名单；
- 每次改变输入偏置前确认 SMU 输出已经关闭；
- 电源状态连续稳定后才继续；
- 检查电源 CV 状态和 SMU compliance；
- 任何异常立即中止；
- `finally` 路径强制执行关断；
- 测试结束后再次确认全部相关输出为 OFF。

## 实测任务二：信号源与示波器联动

DG1022Z CH1 按“正弦波 → 方波 → 三角波”循环切换。切换的是波形类型，不是扫频；发生器目标值保持为 5 kHz、2 Vpp、0 V 偏置。每轮执行：

1. 写入波形设置；
2. 回读波形类型、频率、幅度和偏置；
3. 查询 SCPI 错误队列；
4. 从 MSO5354 CH1 读取 Vpp、最大值、最小值和频率；
5. 读取 1000 个屏幕波形点；
6. 保存参数 CSV、逐点 CSV、无损 JSONL 和最新波形图。

程序还支持暂停、继续和停止。暂停时停止切换与查询并刷新日志；正常停止或异常退出时尝试恢复信号源启动前的波形与输出状态。

目标间隔是 2 秒，实际平均为 2.28 秒，因为每轮还包含多次 SCPI 往返、参数测量、1000 点传输、文件写入和 PNG 重绘。这个帧率是电脑轮询和文件处理速度，不是示波器内部采样率。

## AI 在这次任务中真正完成了什么

- 从编程手册中定位接口、命令和波形数据格式；
- 诊断 Python、VISA、USBTMC、串口与 LAN 连接问题；
- 根据自然语言要求生成和修改控制程序；
- 将安全要求转换成白名单、状态机、限值、回读和异常关断；
- 从单点验证逐步扩展到扫描和持续监控；
- 保存原始值、时间戳、仪器状态和错误信息；
- 生成 CSV、曲线、实时波形与阶段总结；
- 根据实际日志纠正“采集间隔”“1000 点波形”和“示波器采样率”等概念混淆。

AI 没有提高仪器本身的精度、带宽或采样率，也没有替代接线检查、接地、量程、安全授权和工程判断。

## 本次最值得复用的经验

1. “软件能导入”不等于“仪器已连接”，必须逐级验证设备枚举、VISA 资源、身份回读、只读状态和写操作。
2. IP、COM 号和 VISA 资源名会变化，程序应优先发现，不应照抄历史地址。
3. 真实硬件控制应采用“AI 辅助设计 + 确定性程序执行”，不能让对话模型直接绕过限值和联锁。
4. 单点、小范围、低风险验证通过后，再扩大扫描范围和运行时间。
5. 保存原始数据和状态比只保存最终结论更重要，否则后续无法复盘异常。
6. 电脑采集到的波形点数受示波器读取模式、存储深度、传输协议、接口带宽、超时和软件处理能力共同限制。

## 最终评价

这次实践验证的不是“AI 可以取代测试工程师”，而是：AI 可以显著降低仪器资料理解、自动化编程、跨设备集成、数据处理和报告整理的门槛。对于个人、教学和研发实验室，这种方案能用很低的软件增量成本建立灵活的自动化能力；进入生产环境后，则必须继续补齐校准追溯、权限、硬件联锁、版本冻结、异常恢复和质量体系。
